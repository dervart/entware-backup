# backup.sh — резервное копирование Entware на SMB‑шару

Этот скрипт автоматизирует создание и отправку резервной копии каталога `/opt` (Entware) на удалённый SMB‑сервер. Он поддерживает интерактивный режим с отображением прогресса (через `pv`), проверку целостности архива, ротацию старых бэкапов и подробное логирование.
* * *

## Возможности

*   **Создание сжатого архива** — каталог `/opt` упаковывается в `.tar.gz` с исключением самого файла лога.
*   **Интерактивный режим** — при запуске из терминала отображается прогресс создания архива (через `pv`) и загрузки (через `smbclient`).
*   **Проверка архива** — после создания архив проверяется на целостность (`tar tzf`).
*   **Проверка удалённой папки** — если папка на SMB‑шаре отсутствует, она создаётся автоматически.
*   **Загрузка на SMB** — архив отправляется на сервер с помощью `smbclient`.
*   **Верификация загрузки** — после отправки проверяется наличие файла на сервере.
*   **Ротация бэкапов** — на сервере остаются только последние `KEEP_COUNT` архивов (по умолчанию 7).
*   **Логирование** — все действия записываются в `/opt/backup.log` с временными метками.
*   **Безопасная очистка** — перед запуском удаляются старые временные архивы из `/tmp`.
* * *

## Требования

*   **Роутер Keenetic** с установленным **Entware**.
*   **SMB‑клиент** — пакет `samba4-client` (утилита `smbclient`).
*   **Стандартные утилиты** — `tar`, `gzip`, `grep`, `awk`, `wc`, `sort`, `head`, `du`, `rm`, `date` — все они уже присутствуют в BusyBox.
*   **Опционально** — `pv` для отображения прогресса создания архива в интерактивном режиме (рекомендуется).
*   **Опционально** — `pigz` для архивирования в несколько потоков (рекомендуется для роутеров с 3 и более ядрами).

**Важно:** Entware должен быть установлен на раздел с файловой системой **ext2/ext3/ext4** (не NTFS/FAT), иначе работа `cron` и некоторых команд может быть нестабильной.
* * *

## Установка зависимостей

Подключитесь к роутеру по SSH и выполните:

`opkg update`
`opkg install samba4-client`
`opkg install pv`   \# опционально, для прогресса
`opkg install pigz`   \# опционально, для многопоточного архивирования

Если `pv` или `pigz` не находится в репозитории, его можно установить позже или работать без него (скрипт корректно обработает его отсутствие).
* * *

## Настройка

Скопируйте скрипт в файл, например, `/opt/backup.sh`, и сделайте его исполняемым:

`chmod +x /opt/backup.sh`

Отредактируйте переменные в секции `=== CONFIGURATION ===`:

`WORK_DIR`
Каталог для бэкапа (обычно `/opt`)

`SMB_PATH`
Путь к SMB‑шаре в формате `//IP/Share`

`SMB_USER`
Имя пользователя для доступа к шаре

`SMB_PASS`
Пароль пользователя

`REMOTE_DIR`
Имя папки внутри шары, куда будут сохраняться архивы

`KEEP_COUNT`
Количество последних архивов, которые нужно хранить

`LOG_FILE`
Путь к файлу лога (по умолчанию `/opt/backup.log`)

`PIGZ_THREADS`
Количество потоков архивирования (опционально. Если pigz не установлен, будет использован стандартный gz)

Также вы можете изменить имя архива (переменная `BACKUP_NAME` формируется автоматически, но при желании её можно переопределить).
* * *

## Использование

### Ручной запуск

`/opt/backup.sh`

Если вы запускаете скрипт из терминала (интерактивный режим), вы увидите прогресс создания архива (через `pv`) и подробный вывод `smbclient`. Все сообщения также дублируются в лог-файл.

### Проверка лога

`cat /opt/backup.log`

Лог перезаписывается при каждом запуске, поэтому в нём хранится информация только о последнем выполнении.
* * *

## Автоматический запуск по расписанию

Чтобы бэкап выполнялся ежедневно, например, в 02:00, добавьте задание в `cron`:

1.  Установите пакет `cron` (если ещё не установлен):
    
    `opkg install cron`
    
2.  Отредактируйте crontab:
    
    `EDITOR=nano crontab -e`
    
3.  Добавьте строку:
    
    `0 2 * * * /opt/backup.sh`
    
4.  Запустите cron и включите автозагрузку:
    
    `/opt/etc/init.d/S10cron start`
    `/opt/etc/init.d/S10cron enable`
    

**Примечание:** если вы используете встроенный BusyBox cron, убедитесь, что каталог для crontabs существует (`/opt/var/spool/cron/crontabs`) и процесс `crond` запущен.
* * *

## Логирование

*   Лог-файл (`/opt/backup.log`) содержит временные метки и сообщения о каждом шаге.
*   При запуске из терминала сообщения также выводятся на экран.
*   При запуске из cron вывод направляется только в лог-файл.
*   Файл лога **перезаписывается** при каждом запуске — размер не увеличивается со временем.

Если вы хотите сохранять историю, измените перенаправление в cron-строке на `>> /opt/backup.log 2>&1`.
* * *

## Устранение неполадок

### 1\. Ошибка `smbclient: not found`

Установите пакет `samba4-client`:

`opkg install samba4-client`

### 2\. Ошибка `NT_STATUS_BAD_NETWORK_NAME`

Проверьте правильность `SMB_PATH` и доступность сервера. Убедитесь, что шара существует и имя пользователя/пароль верны.

### 3\. Ошибка `NT_STATUS_ACCESS_DENIED`

Проверьте права пользователя на удалённой SMB‑шаре. Убедитесь, что пользователь добавлен в Samba (`smbpasswd -a username`) и имеет разрешение на запись в папку.

### 4\. Архив не создаётся (ошибка `tar`)

Проверьте, что каталог `/opt` существует и не повреждён. Также убедитесь, что в `/tmp` достаточно свободного места (архив временно создаётся там).

### 5\. Не работает `cron`

*   Проверьте, что процесс `crond` запущен (`ps | grep crond`).
*   Убедитесь, что Entware установлен на ext-раздел (не на NTFS/FAT).
*   Проверьте права на исполнение скрипта (`chmod +x /opt/backup.sh`).
*   Попробуйте запустить скрипт вручную, чтобы убедиться, что он работает.

### 6\. Прогресс `pv` не отображается

Установите пакет `pv`:

`opkg install pv`

Либо просто игнорируйте — скрипт всё равно работает корректно.
* * *

## Дополнительные замечания

*   Скрипт **не архивирует** сам файл лога (`backup.log`), чтобы избежать рекурсивного включения.
*   Временный архив хранится в `/tmp` и удаляется после успешной отправки.
*   Ротация происходит на основе имён файлов, поэтому дата в имени должна быть в формате `ГГГГ-ММ-ДД`.
*   Скрипт проверяет наличие всех необходимых команд перед началом работы и завершается с ошибкой, если какой-то команды нет.
